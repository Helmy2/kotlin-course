## `suspend` vs. `Sequence<T>` vs. `Flow<T>`

When returning multiple items from a backend service, choose the right abstraction based on **concurrency** and **evaluation timing**:

| Abstraction | Values Returned | Execution Style | Thread Behavior |
| :--- | :--- | :--- | :--- |
| **`suspend fun fetch(): T`** | Single value | Asynchronous | Suspends carrier thread until computed |
| **`Sequence<T>`** | Multiple values | Synchronous / Lazy | **Blocks** caller thread during computation (CPU/File only) |
| **`Flow<T>`** | Multiple values | **Asynchronous / Reactive** | **Suspends** non-blockingly between emitted values |

```kotlin
// Cold reactive data stream:
fun streamAuditEvents(): Flow<AuditEvent> = flow {
    while (true) {
        val event = databaseQueue.poll() // Non-blocking read
        emit(event)                     // Suspends until collector is ready!
        delay(1000)                     // Non-blocking wait
    }
}
```

## Cold Streams (`Flow`) vs. Hot Streams (`SharedFlow` / `StateFlow`)

```text
Cold Stream (Flow):
Collector A connects ──► Flow starts emitting items (1, 2, 3) from beginning
Collector B connects ──► Flow starts INDEPENDENT execution (1, 2, 3) from beginning

Hot Stream (SharedFlow / StateFlow):
Producer continuously emits events into buffer
Collector A connects ──► Receives events as they happen in real-time
Collector B connects ──► Receives events as they happen in real-time
```

* **Cold `Flow`:** Lazy producer. No code inside `flow { ... }` runs until a terminal operator (`collect`, `toList`, `first`) is called. Each collector gets its own execution.
* **`StateFlow`:** Hot stream holding the **current latest state** (like a reactive variable). Emits immediately to new subscribers. Perfect for in-memory cached exchange rates or system status.
* **`SharedFlow`:** Hot broadcast channel without initial value. Distributes events (like webhook triggers or price tick alerts) to multiple concurrent subscribers.

## Intermediate vs. Terminal Operators & Backpressure

* **Intermediate Operators:** Transform the stream lazily without triggering execution (`map`, `filter`, `take`, `transform`, `flowOn`).
* **Terminal Operators:** Suspend and collect stream items (`collect`, `toList`, `first`, `reduce`).
* **Backpressure Management:** When a producer emits faster than a consumer can process:

```kotlin
val liveRateFlow = flow {
    while (true) {
        emit(gatewayClient.fetchCurrentBtcPrice()) // Fast producer (every 10ms)
        delay(10)
    }
}

liveRateFlow
    // 1. Buffer: Decouples producer from slow consumer with fixed queue
    .buffer(capacity = 64)
    // 2. Conflate: Skips intermediate ticks; consumer always processes only the freshest tick!
    .conflate()
    // 3. Switch upstream emission to Dispatchers.IO:
    .flowOn(Dispatchers.IO)
    .collect { freshPrice ->
        delay(200) // Slow consumer (persisting to DB)
        println("Saved price: $freshPrice")
    }
```

## Spring Boot 3+ Native `Flow` Support (SSE & R2DBC)

Spring Boot 3 WebFlux seamlessly converts a Kotlin `Flow<T>` into a non-blocking streaming response:

```kotlin
@RestController
@RequestMapping("/api/v1/streaming")
class ReactiveStreamingController(
    private val auditRepo: R2dbcAuditRepository,
    private val ratesChannel: SharedFlow<ExchangeRateTick>
) {
    // 1. Server-Sent Events (SSE) stream pushed to browser clients
    @GetMapping("/rates", produces = [MediaType.TEXT_EVENT_STREAM_VALUE])
    fun streamLiveRates(): Flow<ExchangeRateTick> {
        return ratesChannel.asSharedFlow()
    }

    // 2. Streaming thousands of DB rows with constant O(1) memory usage
    @GetMapping("/history/{currency}")
    fun streamHistoricalRates(@PathVariable currency: String): Flow<AuditEntity> {
        return auditRepo.findAllByCurrency(currency.uppercase())
    }
}
```

## Kotlin Channels vs. Flows: Point-to-Point Pipelines

While `Flow` represents a cold stream of values, **`Channel<T>`** represents a **hot point-to-point communication pipeline** between coroutines (like a non-blocking `BlockingQueue`):

| Feature | `Flow<T>` | `Channel<T>` |
| :--- | :--- | :--- |
| **Stream Nature** | Cold (Evaluated per collector) | Hot (Items reside in buffer regardless of consumers) |
| **Subscription Model** | Unicast / Broadcast per collector | Point-to-Point (Each item consumed by **exactly one** worker) |
| **Primary Use Case** | Streaming database queries, event streams, SSE | Worker Pools, Fan-Out / Fan-In task distribution |

```kotlin
import kotlinx.coroutines.channels.Channel

// Worker pool using Channel:
val orderQueue = Channel<String>(capacity = Channel.BUFFERED)

// 1. Producer coroutine:
launch {
    repeat(10) { id -> orderQueue.send("ORD-$id") }
    orderQueue.close()
}

// 2. Three concurrent worker consumers (Fan-Out):
repeat(3) { workerId ->
    launch {
        for (order in orderQueue) {
            println("Worker #$workerId processed $order on ${Thread.currentThread().name}")
        }
    }
}
```

## Type-Safe Builders & DSL Design with `@DslMarker`

Kotlin allows you to design clean, declarative domain-specific languages (DSLs) using **lambdas with receiver (`T.() -> Unit`)**:

```kotlin
// 1. Annotate DSL markers to prevent child scopes from calling outer scope methods accidentally:
@DslMarker
annotation class QueryDsl

@QueryDsl
class SqlQueryBuilder {
    private var tableName: String = ""
    private val conditions = mutableListOf<String>()

    fun from(table: String) { this.tableName = table }
    fun where(condition: String) { conditions.add(condition) }

    fun build(): String = "SELECT * FROM $tableName WHERE " + conditions.joinToString(" AND ")
}

// 2. Top-level builder entrypoint:
fun sql(init: SqlQueryBuilder.() -> Unit): String {
    return SqlQueryBuilder().apply(init).build()
}

// 3. Declarative Call Site:
val query = sql {
    from("merchants")
    where("status = 'ACTIVE'")
    where("balance > 1000")
}
// SELECT * FROM merchants WHERE status = 'ACTIVE' AND balance > 1000
```

## `kotlinx.serialization` vs. Jackson in Backend Systems

While Jackson is the default in Spring MVC, **`kotlinx.serialization`** generates serializers at **compile time** without reflection:

* **Zero Reflection Overhead:** Faster startup, native GraalVM compatibility, and strict enforcement of Kotlin non-null properties and default values out of the box.
* **Built-in Polymorphism:** Automatically serializes `sealed interface` hierarchies using a type discriminator (`"type": "approved"`).

```kotlin
import kotlinx.serialization.Serializable
import kotlinx.serialization.encodeToString
import kotlinx.serialization.json.Json

@Serializable
data class WebhookEvent(
    val eventId: String,
    val source: String = "PAYMOB_GATEWAY", // Default applied automatically if missing in JSON!
    val amountPiasters: Long
)

val jsonCodec = Json { ignoreUnknownKeys = true; encodeDefaults = true }

val payload = jsonCodec.decodeFromString<WebhookEvent>("""{"eventId":"EVT-1","amountPiasters":25000}""")
val rawJson = jsonCodec.encodeToString(payload)
```

## Testing Coroutines & Flows (`kotlinx-coroutines-test`)

Testing asynchronous delays and timeouts with `Thread.sleep()` wastes CI minutes and causes flakiness. 

`runTest` executes coroutines using **Virtual Time (TestScope)**: `delay()` calls are fast-forwarded instantly!

```kotlin
import kotlin.test.Test
import kotlin.test.assertEquals
import kotlinx.coroutines.delay
import kotlinx.coroutines.flow.*
import kotlinx.coroutines.test.runTest
import kotlin.time.Duration.Companion.seconds

class RetryStreamTest {
    @Test
    fun `should emit 3 retry ticks without waiting 30 real seconds`() = runTest {
        val ticksFlow = flow {
            repeat(3) { attempt ->
                delay(10.seconds) // Fast-forwarded instantly by Virtual Time in 2ms!
                emit("Attempt #${attempt + 1}")
            }
        }

        val results = ticksFlow.toList()
        assertEquals(listOf("Attempt #1", "Attempt #2", "Attempt #3"), results)
    }
}
```

## Lab 1: Real-Time Fraud Detection Pipeline with Kotlin `Flow` & Channels

**Scenario:** Process an incoming stream of transaction events. Detect anomalies (transfers $> 50,000$ EGP), apply backpressure buffering, handle upstream errors gracefully without killing the pipeline, and output alerts.

---

## Lab 1: Reference Solution

```kotlin
import kotlinx.coroutines.*
import kotlinx.coroutines.flow.*

data class TransactionEvent(
    val txId: String,
    val amountEgp: Double,
    val countryCode: String
)

class FraudDetectionService {
    fun processTransactionStream(rawEvents: Flow<TransactionEvent>): Flow<String> {
        return rawEvents
            .filter { tx -> tx.amountEgp >= 20_000.0 } // High value threshold
            .map { tx ->
                val riskLevel = if (tx.amountEgp > 50_000.0) "CRITICAL" else "HIGH"
                "ALERT [$riskLevel] [${tx.txId}]: ${tx.amountEgp} EGP (${tx.countryCode})"
            }
            .buffer(capacity = 32) // Backpressure buffer
            .flowOn(Dispatchers.Default) // CPU analysis on Default dispatcher
            .catch { ex ->
                emit("STREAM_ERROR_RECOVERED: ${ex.message}")
            }
    }
}

fun main() = runBlocking {
    val service = FraudDetectionService()

    val incomingEvents = flow {
        emit(TransactionEvent("TX-101", 1500.0, "EG"))
        emit(TransactionEvent("TX-102", 25000.0, "EG"))
        emit(TransactionEvent("TX-103", 80000.0, "AE"))
        throw RuntimeException("Kafka Broker Disconnected")
    }

    service.processTransactionStream(incomingEvents)
        .collect { alert ->
            println(alert)
        }
}
```

## Lab 2: Fast Virtual-Time Pipeline Testing with `runTest`

**Scenario:** Write a unit test that verifies an exponential backoff retry flow (1s, 2s, 4s delays) completes in under 10 real milliseconds using `runTest`.

---

## Lab 2: Reference Solution

```kotlin
import kotlinx.coroutines.delay
import kotlinx.coroutines.flow.*
import kotlinx.coroutines.test.runTest
import kotlin.test.Test
import kotlin.test.assertEquals
import kotlin.time.Duration.Companion.seconds

class ResilientStreamTester {
    fun exponentialRetryFlow(): Flow<Int> = flow {
        var delayTime = 1.seconds
        repeat(3) { attempt ->
            delay(delayTime)
            emit(attempt + 1)
            delayTime *= 2
        }
    }

    @Test
    fun testExponentialBackoffVirtualTime() = runTest {
        val startReal = System.currentTimeMillis()
        val results = exponentialRetryFlow().toList()
        val elapsedReal = System.currentTimeMillis() - startReal

        assertEquals(listOf(1, 2, 3), results)
        // Verify real clock took < 100ms despite 7 seconds of virtual delays:
        assert(elapsedReal < 100) { "Expected virtual fast-forward, took ${elapsedReal}ms" }
        println("Completed 7 seconds of virtual delays in ${elapsedReal}ms real time!")
    }
}
```

## Topic 06 Recap & Key Takeaways

* **Use `Flow<T>` for Non-Blocking Streams:** Replace complex Reactor `Flux` pipelines with cold `Flow`s, `.flowOn()`, and `.catch {}`—and return `Flow<T>` directly from Spring Boot 3+ controllers and R2DBC repositories.
* **Hot State vs. Hot Events:** Use `StateFlow` for state that survives recreation (cached rates, system status) and `SharedFlow` for broadcast events (webhook triggers, alerts).
* **Channels for Worker Queues:** Use `Channel<T>` for hot point-to-point work distribution where each task is handled by a single consumer coroutine.
* **Design Type-Safe DSLs:** Leverage lambdas with receiver and `@DslMarker` to create clean, declarative builders.
* **Reflectionless Serialization:** Use `kotlinx.serialization` for native AOT/GraalVM compilation and strict Kotlin null safety.
* **Instant Virtual-Time Testing:** Leverage `runTest` and `TestScope` to simulate hours of retries and delays in single-digit milliseconds.
