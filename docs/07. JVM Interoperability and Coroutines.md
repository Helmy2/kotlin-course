# Module 1: JVM Interoperability
### Calling Java from Kotlin and Kotlin from Java Seamlessly

## Calling Java from Kotlin: Getters, Setters & Properties

Kotlin automatically maps Java's `getX()` / `setX()` methods into Kotlin property access syntax:

```java
// LegacyCustomer.java
public class LegacyCustomer {
    private String fullName;
    private boolean active;

    public String getFullName() { return fullName; }
    public void setFullName(String fullName) { this.fullName = fullName; }
    public boolean isActive() { return active; }
    public void setActive(boolean active) { this.active = active; }
}
````

```Kotlin
// CustomerService.kt
fun inspectCustomer(javaCustomer: LegacyCustomer) {
    // Accessed as properties—no getFullName() / setFullName() needed!
    javaCustomer.fullName = "Tarek Mansour"
    if (javaCustomer.isActive) {
        println("Active customer: ${javaCustomer.fullName}")
    }
}
```

## The Danger Zone: Platform Types (`T!`)

Because Java does not enforce null safety in its type system, any unannotated Java reference arrives in Kotlin as a **Platform Type (`String!`)**:
- **What `T!` Means:** The Kotlin compiler says _"I don't know if this is nullable or non-null—you decide!"_
- **The Trap:** Assigning `String!` to a non-null `val name: String` without checking can cause an immediate `NullPointerException` if Java returns `null`.

```Kotlin
// Suppose LegacyRepo.findEmailById(id) is unannotated Java returning String
val rawEmail = legacyRepo.findEmailById("USR-10") // Inferred type: String! (Danger!)

// ✅ Best Practice 1: Explicitly type every unannotated Java return as Nullable (T?)
val safeEmail: String? = legacyRepo.findEmailById("USR-10")
val normalized = safeEmail?.lowercase() ?: "unknown@domain.com"
```

## Nullability Annotations & JSpecify

When Java code is annotated with nullability contracts, the Kotlin compiler reads them and enforces strict compile-time null safety automatically!
- **Supported Annotation Families:**
    - **JSpecify (`org.jspecify.annotations`):** `@Nullable`, `@NonNull`, `@NullMarked` (Standard in Spring Framework 6.2+ / Spring Boot 3.4+).
    - **JetBrains / Jakarta / Spring:** `@ org.jetbrains.annotations.NotNull`, `org.springframework.lang.NonNull`.
- **Compiler Flag (`build.gradle.kts`):** Force strict errors on JSR-305 / JSpecify mismatches:

```Kotlin
kotlin {
    compilerOptions {
        freeCompilerArgs.add("-Xjsr305=strict")
    }
}
```

## Calling Kotlin from Java: The 4 Essential `@Jvm*` Annotations

When Java teammates call your Kotlin classes, use these annotations to generate idiomatic Java signatures:

| **Annotation**             | **Where It Goes**                     | **What It Generates for Java Callers**                                                       |
| -------------------------- | ------------------------------------- | -------------------------------------------------------------------------------------------- |
| **`@file:JvmName("...")`** | Top of `.kt` file                     | Customizes the generated class name instead of `FileNameKt`                                  |
| **`@JvmStatic`**           | Inside `object` or `companion object` | Generates a real Java `static` method (`Money.of(...)` instead of `Money.Companion.of(...)`) |
| **`@JvmOverloads`**        | Functions/constructors with defaults  | Generates overloaded Java methods for every default parameter combination                    |
| **`@JvmField`**            | Class property                        | Exposes a public field directly without generating getter/setter methods                     |

---
## `@Jvm*` Annotations in Action

```Kotlin
@file:JvmName("SecurityUtils") // Java calls SecurityUtils.maskToken(...) instead of SecurityUtilsKt
package com.company.security

import java.io.IOException

class TokenValidator @JvmOverloads constructor(
    val issuer: String,
    val clockSkewSeconds: Long = 30L,
    val strictMode: Boolean = true
) {
    @JvmField
    val version: String = "v2.1" // Java accesses validator.version directly

    @Throws(IOException::class) // Declares checked exception in Java bytecode signature!
    fun verifyAgainstRemoteKeys(token: String): Boolean {
        if (token.isBlank()) throw IOException("Empty token")
        return token.startsWith(issuer)
    }

    companion object {
        @JvmStatic
        fun createDefault(): TokenValidator = TokenValidator("[https://auth.internal](https://auth.internal)")
    }
}
```

```Java
// Calling from Java feels 100% native!
TokenValidator v1 = new TokenValidator("[https://auth.internal](https://auth.internal)"); // Thanks to @JvmOverloads
TokenValidator v2 = TokenValidator.createDefault();              // Thanks to @JvmStatic
String ver = v1.version;                                         // Thanks to @JvmField
```

## Annotation Processing & Framework Integration

Modern backend frameworks rely heavily on bytecode proxies, reflection, and compile-time code generation:

1. **`kotlin-spring` (`all-open` compiler plugin):**
    - Spring `@Configuration`, `@Service`, and `@Transactional` require classes to be `open` so CGLIB can subclass them.
    - Applying `kotlin("plugin.spring")` automatically opens any class annotated with `@Component`, `@Service`, `@Transactional`, etc.
2. **`kotlin-jpa` (`no-arg` compiler plugin):**
    - Hibernate requires a zero-argument constructor to instantiate `@Entity` classes via reflection.
    - Applying `kotlin("plugin.jpa")` generates a synthetic no-arg constructor in bytecode without polluting your Kotlin code!
3. **KSP (Kotlin Symbol Processing) vs. KAPT:**
    - Prefer **KSP** over legacy KAPT whenever supported (e.g., Micronaut, Room, Moshi) for up to 2x faster build times.

## Lab 1: Upgrading a Legacy Audit Client for Polyglot Usage

**Scenario:** Your team has a legacy Java `LegacyAuditRecord` class that returns unannotated nullable values, and Java services also need to call your new Kotlin `AuditService` cleanly.

```Kotlin
// Simulated Legacy Java Class (Pretend this comes from an unannotated .jar)
class LegacyJavaAuditRecord(
    val eventId: String?,      // In Java: getEventId() -> could be null!
    val actorUsername: String?, // In Java: getActorUsername() -> could be null!
    val severityCode: Int
)
```

**Tasks:**
1. Create a Kotlin class `AuditEntry` with `@JvmOverloads constructor` taking:
    - `eventId: String`
    - `actor: String = "SYSTEM"`
    - `severity: String = "INFO"`
    - Expose `val schemaVersion: Int = 2` using `@JvmField`.
2. Add a `companion object` with `@JvmStatic` factory method `fromLegacy(record: LegacyJavaAuditRecord?): AuditEntry`:
    - Fail fast with `IllegalArgumentException` if `record` or `record.eventId` is null/blank.
    - Default `actorUsername` to `"SYSTEM"` if null/blank.
    - Map `severityCode` (`1 -> "INFO"`, `2 -> "WARN"`, `3 -> "CRITICAL"`, else `"UNKNOWN"`).
3. Add a method `exportToDisk(filePath: String)` annotated with `@Throws(java.io.IOException::class)` that throws `IOException("Disk full")` if `filePath.startsWith("/readonly")`.
---
## Lab 1: Reference Solution

```Kotlin
import java.io.IOException

class LegacyJavaAuditRecord(
    val eventId: String?,
    val actorUsername: String?,
    val severityCode: Int
)

class AuditEntry @JvmOverloads constructor(
    val eventId: String,
    val actor: String = "SYSTEM",
    val severity: String = "INFO"
) {
    @JvmField
    val schemaVersion: Int = 2

    init {
        require(eventId.isNotBlank()) { "eventId must not be blank" }
    }

    @Throws(IOException::class)
    fun exportToDisk(filePath: String): String {
        if (filePath.startsWith("/readonly")) {
            throw IOException("Cannot write audit entry [$eventId] to read-only path: $filePath")
        }
        return "Wrote [v$schemaVersion] $eventId ($severity) by $actor to $filePath"
    }

    companion object {
        @JvmStatic
        fun fromLegacy(record: LegacyJavaAuditRecord?): AuditEntry {
            val nonNullRecord = requireNotNull(record) { "Legacy audit record cannot be null" }

            val validId = nonNullRecord.eventId
                ?.trim()
                ?.takeIf { it.isNotBlank() }
                ?: throw IllegalArgumentException("Legacy record is missing eventId")

            val resolvedActor = nonNullRecord.actorUsername
                ?.trim()
                ?.takeIf { it.isNotBlank() }
                ?: "SYSTEM"

            val resolvedSeverity = when (nonNullRecord.severityCode) {
                1 -> "INFO"
                2 -> "WARN"
                3 -> "CRITICAL"
                else -> "UNKNOWN"
            }

            return AuditEntry(
                eventId = validId,
                actor = resolvedActor,
                severity = resolvedSeverity
            )
        }
    }
}

fun main() {
    val legacy = LegacyJavaAuditRecord(eventId = "EVT-77", actorUsername = null, severityCode = 3)
    
    // Calling the @JvmStatic factory
    val entry = AuditEntry.fromLegacy(legacy)
    println("Mapped Entry: id=${entry.eventId}, actor=${entry.actor}, sev=${entry.severity}, v=${entry.schemaVersion}")

    // Testing @JvmOverloads default parameters
    val defaultEntry = AuditEntry("EVT-78")
    println(defaultEntry.exportToDisk("/var/log/audit.log"))
}
```

# Module 2: Introduction to Coroutines

### Lightweight Cooperative Multitasking for High-Concurrency Backends

---
## The Thread-Per-Request Bottleneck on the Backend

```Plaintext
Traditional Blocking Thread-Per-Request (Tomcat 200 Threads):
[HTTP Req] ──► [OS Thread #1 (1MB RAM)] ──► Calls DB (Blocked 150ms) ──► Calls Payment API (Blocked 300ms)
                                             ▲ OS Thread sits completely IDLE for 450ms!

Kotlin Coroutines (Cooperative Suspension):
[HTTP Req] ──► [Coroutine (Few Hundred Bytes)] ──► Calls DB (Suspends!)
                                                    └─► Worker Thread is FREED to serve 1,000 other requests!
```

- **OS Threads are Expensive:** ~1 MB stack allocation per thread; expensive kernel context switches.
- **Coroutines are Ultra-Lightweight:** You can run **100,000+ concurrent coroutines** in a few dozen megabytes of heap memory.
---
## Coroutines vs. Threads: Side-by-Side Comparison

| **Dimension**        | **OS Thread (java.lang.Thread)**                 | **Kotlin Coroutine**                                             |
| -------------------- | ------------------------------------------------ | ---------------------------------------------------------------- |
| **Memory Footprint** | ~1 MB reserved stack                             | A few hundred bytes on the heap                                  |
| **Scheduling**       | Preemptive (OS Kernel switches threads)          | Cooperative (Suspends at explicit `suspend` points)              |
| **Blocking Cost**    | `Thread.sleep()` blocks the underlying OS thread | `delay()` suspends the coroutine **without** blocking the thread |
| **Creation Limit**   | Thousands (~2,000–10,000 before OOM/thrashing)   | Hundreds of thousands / Millions                                 |

---
## How `suspend` Works Under the Hood (CPS)

Marking a function with `suspend` tells the Kotlin compiler to rewrite it using **Continuation-Passing Style (CPS)**:

```Kotlin
// What you write:
suspend fun fetchUserProfile(userId: String): UserProfile {
    val token = authService.acquireToken()      // Suspension Point 1
    val profile = userClient.getProfile(token)  // Suspension Point 2
    return profile
}

// What the compiler generates in JVM Bytecode (Conceptual):
// Object fetchUserProfile(String userId, Continuation<UserProfile> completion)
```

- The compiler transforms the function into a **state machine** (`label = 0`, `label = 1`, etc.) stored in a lightweight `Continuation` object.
- **Crucial Rule:** A `suspend` function can only be called from another `suspend` function or inside a coroutine builder (`launch`, `async`, `runBlocking`).

# Module 3: Structured Concurrency

### Scopes, Builders, Dispatchers, and Bulletproof Error Handling

---
## What is Structured Concurrency?

In legacy concurrency (`CompletableFuture`, raw threads), firing background tasks often leads to **leaked threads** that keep running even after the HTTP request fails or times out.

**Kotlin's 3 Laws of Structured Concurrency:**
1. Every coroutine must run inside a **`CoroutineScope`** with a bounded lifecycle.
2. **Parent Waits for Children:** A parent coroutine cannot complete until all of its child coroutines have completed.
3. **Automatic Cancellation Propagation:**
    - If a parent scope is cancelled (e.g., user disconnects), all child coroutines are automatically cancelled.
    - If a child coroutine throws an uncaught exception, it cancels its siblings and propagates the failure up to the parent.


---
## Coroutine Builders: `launch` vs. `async` vs. `coroutineScope`

```Kotlin
import kotlinx.coroutines.*

// Parallel Fan-Out inside a Service Method
suspend fun loadDashboardData(userId: String): String = coroutineScope {
    // 1. async: Starts concurrent child coroutine that returns a Deferred<T> result
    val profileDeferred: Deferred<String> = async {
        delay(200) // Simulating non-blocking HTTP call
        "Profile($userId)"
    }

    val ordersDeferred: Deferred<List<String>> = async {
        delay(300) // Runs in PARALLEL with profileDeferred!
        listOf("ORD-1", "ORD-2")
    }

    // 2. launch: Fire-and-forget child coroutine (still awaited by coroutineScope before returning!)
    launch {
        delay(100)
        println("Recorded telemetry for $userId")
    }

    // Total elapsed time is ~300ms (max of parallel tasks), NOT 200+300+100 = 600ms!
    val profile = profileDeferred.await()
    val orders = ordersDeferred.await()
    "$profile -> Orders: $orders"
}
```

---
## Sequential vs. Concurrent Trap!

> **Common Backend Bug:** Calling `suspend` functions back-to-back inside a function runs them **sequentially**, not in parallel!
> 

```Kotlin
// ❌ SLOW (Sequential - Takes 200ms + 300ms = 500ms)
suspend fun fetchSequential(): Pair<String, String> {
    val a = callServiceA() // Waits 200ms until finished!
    val b = callServiceB() // Only starts AFTER Service A finishes (300ms)
    return a to b
}

// ✅ FAST (Concurrent - Takes max(200ms, 300ms) = 300ms)
suspend fun fetchConcurrent(): Pair<String, String> = coroutineScope {
    val aDeferred = async { callServiceA() } // Starts immediately
    val bDeferred = async { callServiceB() } // Starts immediately in parallel
    aDeferred.await() to bDeferred.await()
}
```

---
## Coroutine Dispatchers: Choosing the Right Thread Pool

A `CoroutineDispatcher` determines which thread or thread pool executes the coroutine:

| **Dispatcher**                         | **Thread Pool Size**                                                  | **Backend Use Case**                                                                         |
| -------------------------------------- | --------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| **`Dispatchers.Default`**              | `# of CPU Cores` (min 2)                                              | CPU-intensive work: JSON parsing large payloads, cryptography, sorting, complex pricing math |
| **`Dispatchers.IO`**                   | Elastic (Up to 64 threads or `# cores`, configurable)                 | **Blocking** legacy I/O: JDBC queries, blocking file reads, legacy Java SDK calls            |
| **`Dispatchers.Unconfined`**           | Caller thread (until first suspension)                                | Rare—unit testing or specific framework internals                                            |
| **Virtual Thread Dispatcher (JDK 21)** | `Executors.newVirtualThreadPerTaskExecutor().asCoroutineDispatcher()` | Combining Kotlin structured concurrency with Project Loom Virtual Threads!                   |

```Kotlin
// Switching context safely for a blocking legacy JDBC or File operation:
suspend fun readLegacyCert(path: String): String = withContext(Dispatchers.IO) {
    java.nio.file.Files.readString(java.nio.file.Path.of(path))
}
```

---
## `coroutineScope` vs. `supervisorScope`: Handling Partial Failures

- **`coroutineScope { ... }` (All-or-Nothing):**
    - If **any** child `async` fails with an exception, all sibling coroutines are immediately cancelled and the whole block rethrows the exception.
    - _Use Case:_ Financial transfer where both Fraud Check AND Balance Check must succeed.
- **`supervisorScope { ... }` (Independent Children / Graceful Degradation):**
    - A failure in one child does **not** cancel its siblings!
    - _Use Case:_ Product Page aggregator where `fetchCoreProduct()` is mandatory, but if `fetchRecommendations()` fails, you catch it and return an empty recommendation list `emptyList()`.
---        
```Kotlin
suspend fun loadProductPage(productId: String): String = supervisorScope {
    val coreProduct = async { fetchProductDetails(productId) }
    val recommendations = async { fetchAiRecommendations(productId) } // Might fail!

    val product = coreProduct.await() // Rethrows if core product fails
    val recs = runCatching { recommendations.await() }
        .getOrElse { ex ->
            println("Recommendations degraded: ${ex.message}")
            emptyList()
        }
    "Product: $product | Recs: $recs"
}
```

---
## Cooperative Cancellation & The `CancellationException` Trap

When a coroutine is cancelled (e.g., via `withTimeout(500)` or sibling failure), it throws a `CancellationException` at the next suspension point.

> **CRITICAL RULE:** Never swallow `CancellationException` inside a generic `catch (e: Exception)` block without rethrowing it! Swallowing it breaks structured concurrency and creates zombie coroutines.
>   

```Kotlin
import kotlin.coroutines.cancellation.CancellationException

suspend fun safeExternalCall(): String {
    return try {
        delay(200)
        "OK"
    } catch (e: CancellationException) {
        throw e // ✅ ALWAYS rethrow CancellationException!
    } catch (e: Exception) {
        // Handle genuine business/network exceptions
        "FALLBACK_VALUE"
    }
}
```

## Non-Blocking HTTP Client (`WebClient` + `awaitBody`)

Spring's `WebClient` ships with Kotlin coroutine extensions (`awaitBody`, `awaitBodilessEntity`, `awaitExchange`):

```Kotlin
import org.springframework.stereotype.Service
import org.springframework.web.reactive.function.client.WebClient
import org.springframework.web.reactive.function.client.awaitBody
import org.springframework.web.reactive.function.client.awaitBodyOrNull

@Service
class InventoryGateway(
    private val webClient: WebClient
) {
    suspend fun checkStock(sku: String): StockResponseDto {
        return webClient.get()
            .uri("/internal/inventory/{sku}", sku)
            .retrieve()
            .awaitBody<StockResponseDto>() // Suspends without blocking any OS thread!
    }

    suspend fun fetchOptionalPromo(code: String): PromoDto? {
        return webClient.get()
            .uri("/internal/promos/{code}", code)
            .retrieve()
            .awaitBodyOrNull<PromoDto>() // Returns null on 404/empty body
    }
}
```

## Wrapping Blocking Legacy Dependencies Safely in Spring

If your Spring application uses **blocking JDBC / JPA (Hibernate)** alongside coroutines, never run blocking DB queries directly on the non-blocking event loop (`reactor-http-nio`):

```Kotlin
import kotlinx.coroutines.Dispatchers
import kotlinx.coroutines.withContext
import org.springframework.stereotype.Service

@Service
class HybridOrderService(
    private val jpaOrderRepository: LegacyJpaOrderRepository, // Blocking JDBC
    private val inventoryGateway: InventoryGateway            // Non-blocking WebClient
) {
    suspend fun getOrderWithLiveStock(orderId: String): EnrichedOrderDto = coroutineScope {
        // 1. Offload blocking JPA call to Dispatchers.IO
        val orderDeferred = async(Dispatchers.IO) {
            jpaOrderRepository.findById(orderId)
                .orElseThrow { IllegalArgumentException("Order $orderId not found") }
        }

        val order = orderDeferred.await()
        // 2. Non-blocking HTTP call via WebClient
        val stock = inventoryGateway.checkStock(order.sku)

        EnrichedOrderDto(orderId = order.id, sku = order.sku, availableQty = stock.available)
    }
}
```

```Kotlin
import kotlinx.coroutines.*
import kotlin.system.measureTimeMillis

suspend fun checkNationalId(id: String): Boolean {
    delay(300)
    return id.startsWith("2") || id.startsWith("3")
}

suspend fun checkSanctionsList(name: String): Boolean {
    delay(400)
    return !name.contains("BLOCKED", ignoreCase = true)
}

suspend fun checkCreditScore(id: String): Int {
    delay(350)
    return 740
}

suspend fun verifyCustomerParallel(id: String, name: String): String = coroutineScope {
    val validIdDeferred = async { checkNationalId(id) }
    val cleanSanctionsDeferred = async { checkSanctionsList(name) }
    val creditScoreDeferred = async { checkCreditScore(id) }

    val isIdValid = validIdDeferred.await()
    val isSanctionsClean = cleanSanctionsDeferred.await()
    val score = creditScoreDeferred.await()

    if (isIdValid && isSanctionsClean && score >= 650) {
        "APPROVED (Score: $score)"
    } else {
        "REJECTED"
    }
}

suspend fun verifyWithSla(id: String, name: String, timeoutMs: Long): String {
    return withTimeoutOrNull(timeoutMs) {
        verifyCustomerParallel(id, name)
    } ?: "SLA_TIMEOUT"
}

fun main() = runBlocking {
    val elapsedMs = measureTimeMillis {
        val status = verifyWithSla(id = "30102031234567", name = "Salma Adel", timeoutMs = 600L)
        println("KYC Status: $status")
    }
    println("Completed parallel KYC in ${elapsedMs}ms (Expected ~400-430ms, well under 1050ms!)")

    val timeoutStatus = verifyWithSla(id = "30102031234567", name = "Salma Adel", timeoutMs = 200L)
    println("Strict SLA Test: $timeoutStatus") // SLA_TIMEOUT
}
```

```Kotlin
import kotlin.coroutines.cancellation.CancellationException

        delay(200)
        require(orderId.startsWith("ORD-")) { "Invalid Order ID: $orderId" }
        return 1200.0
    }

    suspend fun fetchLoyaltyPoints(userId: String, simulateFailure: Boolean): Int {
        delay(250)
        if (simulateFailure) throw RuntimeException("Loyalty microservice 503 Unavailable")
        return 450
    }

    suspend fun estimateShipping(city: String, simulateSlowNetwork: Boolean): Double {
        delay(if (simulateSlowNetwork) 800 else 150)
        return if (city.equals("Cairo", ignoreCase = true)) 35.0 else 60.0
    }
}

class CheckoutAggregatorService(
    private val gateways: DownstreamGateways = DownstreamGateways()
) {
    suspend fun buildCheckoutSummary(
        orderId: String,
        userId: String,
        city: String,
        loyaltyOutage: Boolean = false,
        shippingCongested: Boolean = false
    ): CheckoutSummary = supervisorScope {
        val warnings = mutableListOf<String>()

        // Start all 3 calls concurrently inside supervisorScope
        val subtotalDeferred = async {
            gateways.fetchOrderSubtotal(orderId)
        }

        val loyaltyDeferred = async {
            gateways.fetchLoyaltyPoints(userId, loyaltyOutage)
        }

        val shippingDeferred = async {
            withTimeout(300L) {
                gateways.estimateShipping(city, shippingCongested)
            }
        }

        // 1. Critical call: If subtotal fails, cancel remaining children and rethrow!
        val subtotal = try {
            subtotalDeferred.await()
        } catch (ex: Throwable) {
            loyaltyDeferred.cancel()
            shippingDeferred.cancel()
            throw ex
        }

        // 2. Non-critical Loyalty call: Graceful fallback on failure
        val loyaltyPoints = try {
            loyaltyDeferred.await()
        } catch (e: CancellationException) {
            throw e
        } catch (e: Exception) {
            warnings.add("Loyalty service unavailable (${e.message}); defaulted to 0 pts")
            0
        }

        // 3. Non-critical Shipping call: Graceful fallback on TimeoutCancellationException or error
        val shippingFee = try {
            shippingDeferred.await()
        } catch (e: TimeoutCancellationException) {
            warnings.add("Shipping estimator timed out (>300ms); applied flat 50.0 fee")
            50.0
        } catch (e: CancellationException) {
            throw e
        } catch (e: Exception) {
            warnings.add("Shipping estimator error; applied flat 50.0 fee")
            50.0
        }

        CheckoutSummary(
            orderId = orderId,
            subtotal = subtotal,
            loyaltyPointsAvailable = loyaltyPoints,
            shippingFee = shippingFee,
            warnings = warnings
        )
    }
}

fun main() = runBlocking {
    val aggregator = CheckoutAggregatorService()

    // Scenario 1: All services healthy
    val healthy = aggregator.buildCheckoutSummary("ORD-100", "USR-1", "Cairo")
    println("Healthy Run:  $healthy")

    // Scenario 2: Loyalty service crashes AND Shipping service is slow (Graceful Degradation!)
    val degraded = aggregator.buildCheckoutSummary(
        orderId = "ORD-101",
        userId = "USR-1",
        city = "Cairo",
        loyaltyOutage = true,
        shippingCongested = true
    )
    println("Degraded Run: $degraded")
}
```
