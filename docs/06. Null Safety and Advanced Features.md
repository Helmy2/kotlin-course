# Module 1: Null Safety in the Type System
### Moving `NullPointerException` from Production Runtime to Compile Time

---

## The "Billion-Dollar Mistake" in Backend Systems

* **The Java Reality:** Any reference type (`String`, `Account`, `List`) can secretly hold `null`.
* **Defensive Clutter:** Backend services become littered with deeply nested `null` checks or verbose `Optional<T>` wrappers just to inspect an incoming payload.
* **Kotlin's Solution:** Nullability is baked directly into the **compile-time type system** with zero runtime wrapper overhead.

```kotlin
var nonNullToken: String = "jwt-xyz-99"
// nonNullToken = null // ❌ Compilation Error: Null can not be a value of a non-null type String

var optionalHeader: String? = "Bearer jwt-xyz-99"
optionalHeader = null  // ✅ Allowed! Marked explicitly as nullable (String?)
```

---

## Nullable (`T?`) vs. Non-Null (`T`) Types

| Type | Meaning | Allowed Operations | JVM Bytecode Representation |
| :--- | :--- | :--- | :--- |
| **`String`** | Guaranteed non-null reference | Call `.length`, `.uppercase()`, pass to non-null params freely | `java.lang.String` + `@NotNull` metadata |
| **`String?`** | Can hold a `String` **OR** `null` | **Restricted!** Direct method/property access is blocked by the compiler | `java.lang.String` + `@Nullable` metadata |

* **Subtyping Rule:** `String` is a subtype of `String?`. You can always pass a non-null `String` where a `String?` is expected, but never the reverse without handling the `null` case first.

---

## The Null-Safety Operator Toolkit

1. **Safe Call Operator (`?.`):** Evaluates only if non-null; otherwise short-circuits to `null`.
2. **Elvis Operator (`?:`):** Provides a default value or fail-fast action (`return` / `throw`) when the left side is `null`.
3. **Safe Cast Operator (`as?`):** Casts safely or returns `null` instead of throwing `ClassCastException`.

```kotlin
fun extractPostalCode(order: OrderPayload?): String {
    // 1. Safe call chain (?.) + 2. Elvis fallback (?:)
    val zip = order?.customer?.billingAddress?.postalCode ?: "00000"

    // Fail-fast guard clause using Elvis + throw (Nothing type)
    val paymentId = order?.paymentId
        ?: throw IllegalArgumentException("Missing paymentId in order payload")

    return "$paymentId:$zip"
}
```

---

## The Not-Null Assertion Operator (`!!`)

* **What it does:** Forcefully converts any nullable type `T?` into a non-null `T`, throwing a `NullPointerException` immediately if the value is `null`.
* **Why it exists:** Escape hatch for legacy Java interop or framework lifecycle properties that the compiler cannot verify.
* **Team Code Review Rule:**
  * **Never** chain multiple assertions (`user!!.profile!!.id`).
  * In production backend code, prefer `requireNotNull(value) { "Clear domain error message" }` or `checkNotNull(value) { ... }` over `!!`.

```kotlin
// ❌ Bad: Generic NPE stack trace with zero business context
val rawId = request.headers["X-Request-Id"]!!

// ✅ Good: Descriptive exception message for observability logs
val correlationId = requireNotNull(request.headers["X-Request-Id"]) {
    "Missing mandatory X-Request-Id header on incoming API call"
}
```

---

## Smart Casts & Contract Checks

* **Automatic Promotion:** Once you check that a local `val` is not `null` (via `if`, `when`, or an early `?: return`), the Kotlin compiler **automatically smart-casts** the variable from `T?` to `T` in the remaining scope.
* **Limitation on Mutable Properties (`var`):**
  * The compiler **cannot** smart-cast a mutable class property (`var`) because another thread or custom getter could change its value between the `null` check and usage.

```kotlin
fun processCustomerEmail(email: String?) {
    if (email == null) return

    // 'email' is automatically smart-cast from String? to non-null String here!
    println("Sending receipt to ${email.trim().lowercase()}")
}
```

# Module 2: Working with Nullable Collections
### Distinguishing Missing Elements from Missing Containers

---

## The Three Flavors of Collection Nullability

Understanding the exact placement of `?` in collection signatures is vital when designing repository and API interfaces:

| Signature | Can the List reference itself be `null`? | Can the elements inside the list be `null`? | Backend Interpretation |
| :--- | :--- | :--- | :--- |
| **`List<String>`** | No | No | Standard clean domain list (Always prefer this!) |
| **`List<String?>`** | No | **Yes** | Batch query result where specific rows/keys failed lookup |
| **`List<String>?`** | **Yes** | No | Optional JSON array filter in a PATCH/search request |
| **`List<String?>?`** | **Yes** | **Yes** | Legacy unvalidated external payload (Sanitize immediately!) |

---

## Essential Stdlib Helpers for Nullable Collections

* **`filterNotNull()`:** Strips out `null` elements and narrows `List<T?>` directly into `List<T>`.
* **`mapNotNull { ... }`:** Combines transformation and null-filtering in a single pass.
* **`firstOrNull()` / `singleOrNull()`:** Safe alternatives to exception-throwing queries on empty lists.
* **`orEmpty()`:** Converts a nullable `List<T>?` or `String?` into `emptyList()` or `""`.

```kotlin
val rawTags: List<String?>? = listOf("  urgent ", null, "", "vip")

val cleanTags: List<String> = rawTags
    .orEmpty()                                      // List<String?>? -> List<String?>
    .mapNotNull { tag -> tag?.trim()?.takeIf { it.isNotEmpty() } } // -> List<String>
// Result: ["urgent", "vip"]
```

## Lab 1: Sanitizing Unreliable External Payloads

**Scenario:** Your backend ingests batch payment notifications from a third-party gateway where fields are frequently missing or malformed.

**Tasks:**
1. **Guard Clause Validation:** Design a processor function `processWebhook(payload: WebhookPayload?): ValidatedBatch` that accepts a nullable payload wrapper containing a nullable `transactionId`, nullable `customerEmail`, and nullable `currency`.
   * Use the Elvis operator (`?:`) with `IllegalArgumentException` to fail fast if `transactionId` is missing or blank.
   * Default a missing `currency` code to `"EGP"`, and normalize it to uppercase using safe calls.
2. **Batch Sanitization:** Given `rawAmounts: List<String?>?`, convert it into a clean `List<Double>` of valid positive amounts:
   * Handle the nullable list container safely using `orEmpty()`.
   * Use `mapNotNull` along with `toDoubleOrNull()` and `filter` so that blanks, `null`s, non-numeric strings, and negative numbers are cleanly discarded in one pipeline.

---

## Lab 1: Solution Walkthrough & Architecture Notes

* **Step 1 Verification (Guard Clauses):**
  * By combining `val txId = payload?.transactionId?.takeIf { it.isNotBlank() } ?: throw IllegalArgumentException(...)`, the compiler immediately promotes `payload` AND `txId` to non-null types for the rest of the function body—eliminating nested `if (payload != null)` blocks.
* **Step 2 Verification (Collection Pipeline):**
  * Chaining `rawAmounts.orEmpty().mapNotNull { it?.trim()?.toDoubleOrNull() }.filter { it > 0.0 }` guarantees a non-null `List<Double>` output with zero `NumberFormatException` or `NullPointerException` risk.

---

## Lab 1: Reference Solution (Part 1 — Models & Processor)

```kotlin
data class WebhookPayload(
    val transactionId: String?,
    val customerEmail: String?,
    val currency: String?,
    val rawAmounts: List<String?>?
)

data class ValidatedBatch(
    val transactionId: String,
    val customerEmail: String,
    val currency: String,
    val validAmounts: List<Double>
)
```
---
```kotlin
fun processWebhook(payload: WebhookPayload?): ValidatedBatch {
    // 1. Fail-fast guard clauses with Elvis (?:)
    val txId = payload?.transactionId?.takeIf { it.isNotBlank() }
        ?: throw IllegalArgumentException("Missing or blank transaction ID")

    // Smart-cast kicks in: 'payload' is now guaranteed non-null!
    val email = payload.customerEmail?.trim()?.lowercase()
        ?: "anonymous@internal.local"

    val normalizedCurrency = payload.currency
        ?.trim()
        ?.takeIf { it.isNotEmpty() }
        ?.uppercase()
        ?: "EGP"

    // 2. Sanitize nullable collection & elements in one pipeline
    val cleanAmounts: List<Double> = payload.rawAmounts
        .orEmpty()
        .mapNotNull { raw -> raw?.trim()?.toDoubleOrNull() }
        .filter { amount -> amount > 0.0 }

    return ValidatedBatch(txId, email, normalizedCurrency, cleanAmounts)
}
```

# Module 3: Data Classes
### First-Class Value Objects, DTOs, and Domain Events

---

## What Adding the `data` Keyword Gives You

Declaring a class as a `data class` instructs the compiler to automatically generate five essential methods based on the properties declared in the **primary constructor**:

1. **`equals(other)`:** Structural equality (compares property values, not memory addresses).
2. **`hashCode()`:** Consistent hash generation for safe usage as keys in `HashMap` or elements in `HashSet`.
3. **`toString()`:** Clean diagnostic output (`OrderDto(id=101, status=PAID)`), great for structured logging.
4. **`copy(...)`:** Creates a shallow clone while allowing specific properties to be overridden via named arguments.
5. **`component1()`, `component2()`, ...:** Enables positional destructuring declarations.

---

## Data Class Rules & Hidden Corner Cases

* **Structural Requirements:**
  * The primary constructor must have at least one `val` or `var` parameter.
  * Data classes cannot be `abstract`, `open`, `sealed`, or `inner` (though they can implement interfaces and extend sealed classes).
* **The Body Property Trap:**
  * Properties declared inside the class body `{ ... }` (outside the primary constructor `(...)`) are **excluded** from `equals()`, `hashCode()`, `toString()`, and `copy()`.
* **Immutability Best Practice:**
  * Always use `val` for data class properties. Mutating a `var` property after inserting a data class into a `HashSet` or `HashMap` changes its `hashCode` and corrupts bucket lookups!

---

## Immutable State Transitions with `copy()` & Destructuring

```kotlin
data class PaymentOrder(val id: String, val amount: Double, val status: String = "PENDING")

val initial = PaymentOrder(id = "ORD-10", amount = 500.0)

// 1. Functional state transition via .copy() (initial remains untouched!)
val settled = initial.copy(status = "SETTLED")

// 2. Positional Destructuring
val (orderId, total, currentStatus) = settled
```

* **Destructuring Warning in Backend DTOs:**
  * Destructuring (`val (id, email, role) = userDto`) relies on **positional** `componentN()` calls, not property names.
  * If a developer reorders two `String` fields in the `data class` constructor later, positional destructuring will silently swap values without a compiler error! Reserve destructuring for pairs, map entries, and small tuples.

---

## Backend Caution: Data Classes vs. JPA / Hibernate Entities

> **Never blindly use `data class` for JPA `@Entity` classes!**

| JPA / Hibernate Expectation | Kotlin `data class` Behavior | What Breaks? |
| :--- | :--- | :--- |
| Mutable fields, `open` classes & methods for lazy-loading proxies | `final` by default (even with `all-open`, `copy()` and `componentN` ignore proxies) | Lazy relationships (`@OneToMany`) get triggered accidentally |
| Stable `equals`/`hashCode` across entity lifecycle (before & after DB ID generation) | `hashCode()` computed from all primary constructor fields (including auto-generated `id`) | Entities disappear from `Set`s after `entityManager.persist()` assigns an ID |
| Safe bidirectional references | Auto-generated `toString()` traverses all constructor properties | `StackOverflowError` on bidirectional parent/child relations |

* **Rule of Thumb:** Use `data class` for **DTOs, API Requests/Responses, Domain Events, and Value Objects**. Use standard classes (with custom ID-based `equals`/`hashCode`) for **JPA `@Entity` models**.

# Module 4: Extension Functions & Properties
### Clean Domain Mapping Without Utility Class Sprawl

---

## How Extension Functions Work

* **Concept:** Add new functions or computed properties to an existing class (even final JDK classes like `String`, `Instant`, or third-party library classes) without inheriting from it or modifying its source code.
* **Receiver Type & `this`:** The type being extended is called the **Receiver Type**. Inside the extension body, `this` refers to the instance on which the function was invoked.
* **Zero Runtime Overhead:** Compiled into static Java methods where the receiver object is passed as the first parameter.

```kotlin
// Adding a domain extension function to java.lang.String
fun String.maskSensitiveToken(): String =
    if (this.length <= 4) "****" else "****-${this.takeLast(4)}"

// Adding a computed extension property
val Int.megabytesInBytes: Long
    get() = this * 1024L * 1024L

println("secret-key-9821".maskSensitiveToken()) // ****-9821
```

---

## Extension Functions: Static Dispatch & Encapsulation

1. **Resolved Statically (No Polymorphic Override):**
   * Extension functions are bound at **compile time** based on the declared variable type, not the runtime object type.
2. **Member Always Wins:**
   * If a class already has a member function with the exact same signature as an extension function, the member function will always take precedence.
3. **Respects Visibility:**
   * Extensions cannot access `private` or `protected` members of the class they extend—they only have access to `public` and `internal` APIs.
4. **Nullable Receivers (`T?.ext()`):**
   * You can define extensions directly on nullable types (like standard library's `CharSequence?.isNullOrBlank()`), checking `if (this == null)` safely inside the extension body.

---

## Idiomatic Backend Pattern: Layered Mapping Extensions

Instead of creating bloated `UserMapper`, `OrderConverter`, or `StringUtils` classes:

* **API -> Domain:** Define `.toDomainCommand()` as an extension on `CreateOrderRequestDto`.
* **Domain -> Persistence:** Define `.toEntity()` and `.toDomainModel()` inside the repository package.
* **Domain -> Response:** Define `.toResponseDto()` to keep serialization concerns out of core entities.

```kotlin
// Clean, discoverable autocomplete at the controller boundary:
fun CreateUserRequestDto.toDomain(): User = User(
    id = UUID.randomUUID().toString(),
    email = this.email.trim().lowercase(),
    role = Role.valueOf(this.role.uppercase())
)
```

---

## Functional Error Handling with `Result<T>` & `runCatching`

When mapping untrusted external payloads or calling fallible operations, Kotlin's standard library provides **`Result<T>`** as a lightweight wrapper representing either a **Success(`T`)** or a **Failure(`Throwable`)**:

```kotlin
// runCatching executes the block and captures any exception into Result.failure(ex)
fun parsePort(raw: String): Result<Int> = runCatching {
    val port = raw.trim().toInt()
    require(port in 1024..65535) { "Port $port out of valid range" }
    port // Returned as Result.success(port)
}

// Handling the outcome cleanly at the call site:
parsePort("8080")
    .onSuccess { port -> println("Binding server to port $port") }
    .onFailure { ex -> println("Invalid config: ${ex.message}") }
```

# Module 5: Objects, Singletons & Companion Objects
### Replacing `static` with First-Class Object Declarations

---

## The `object` Keyword: Thread-Safe Singletons

Kotlin has no `static` keyword. Instead, when you need a single instance of a class, you declare an **`object`**:

* **JVM Guarantee:** Compiled to a class with a `private` constructor and a `public static final INSTANCE` field initialized lazily and safely by the JVM classloader.
* **Full OOP Capabilities:** Unlike static utility methods in Java, a Kotlin `object` can implement interfaces (`Serializer`, `HealthIndicator`) and be passed around as a dependency!

```kotlin
object SystemMetricsRegistry : HealthIndicator {
    private val requestCount = java.util.concurrent.atomic.AtomicLong(0)

    fun recordHit() = requestCount.incrementAndGet()
    override fun isHealthy(): Boolean = true
}
```

---

## Companion Objects: Factory Methods & Constants

When you need functionality tied to a class *name* rather than a specific instance of that class, declare a **`companion object`** inside the class:

```kotlin
@ConsistentCopyVisibility
data class ApiKey private constructor(val value: String) {
    companion object {
        const val PREFIX = "ak_live_"

        fun generate(rawSecret: String): ApiKey {
            require(rawSecret.length >= 16) { "Secret too short" }
            return ApiKey("$PREFIX$rawSecret")
        }
    }
}

val key = ApiKey.generate("9988776655443322") // Validated factory call!
```

* **`@ConsistentCopyVisibility` (Kotlin 2.0+):** Ensures a `data class` with a `private constructor` also keeps its generated `.copy()` method private so callers cannot bypass factory validation.

## Lab 2: Rich Domain Modeling with Data Classes & Companion Factories

**Scenario:** You are designing the core domain model for an e-commerce checkout service.

**Tasks:**

## Lab 2: Reference Solution (Part 1 — `Money` Value Object)

```kotlin
@ConsistentCopyVisibility
data class Money private constructor(
    val amount: BigDecimal,
    val currency: String
) {
    fun multiply(factor: Double): Money {
        require(factor >= 0.0) { "Multiplication factor cannot be negative: $factor" }
        val scaledAmount = amount
            .multiply(BigDecimal.valueOf(factor))
            .setScale(SCALE, RoundingMode.HALF_UP)
        return Money(amount = scaledAmount, currency = currency)
    }

    override fun toString(): String = "$amount $currency"

    companion object {
        const val DEFAULT_CURRENCY = "EGP"
        private const val SCALE = 2
        private val SUPPORTED_CURRENCIES = setOf("EGP", "USD", "EUR")

        fun of(amount: Double, currency: String = DEFAULT_CURRENCY): Money {
            require(amount >= 0.0) { "Money amount cannot be negative: $amount" }
            val normalizedCurrency = currency.trim().uppercase()
            require(normalizedCurrency in SUPPORTED_CURRENCIES) {
                "Unsupported currency: $normalizedCurrency"
            }

            val roundedAmount = BigDecimal.valueOf(amount)
                .setScale(SCALE, RoundingMode.HALF_UP)

            return Money(amount = roundedAmount, currency = normalizedCurrency)
        }

        fun zero(currency: String = DEFAULT_CURRENCY): Money = of(0.0, currency)
    }
}
```

## Lab 2: Reference Solution (Part 2 — `OrderSnapshot` & Verification)

```kotlin
data class OrderSnapshot(
    val orderId: String,
    val items: List<String>,
    val total: Money,
    val status: String = "CREATED"
) {
    init {
        require(orderId.isNotBlank()) { "Order ID must not be blank" }
        require(items.isNotEmpty()) { "Order must contain at least one item" }
    }

    fun applyDiscount(discountPercent: Int): OrderSnapshot {
        require(discountPercent in 1..100) {
            "Discount percent must be between 1 and 100, got $discountPercent"
        }
        val retentionFactor = (100 - discountPercent) / 100.0
        return this.copy(
            total = total.multiply(retentionFactor),
            status = "DISCOUNTED"
        )
    }
}

fun main() {
    val initialTotal = Money.of(amount = 1250.556) // Rounds to 1250.56 EGP
    val originalOrder = OrderSnapshot("ORD-2026-881", listOf("Keyboard", "USB-C Hub"), initialTotal)
    val discountedOrder = originalOrder.applyDiscount(discountPercent = 20)

    println("Original:   $originalOrder")   // total=1250.56 EGP, status=CREATED
    println("Discounted: $discountedOrder") // total=1000.45 EGP, status=DISCOUNTED
    println("Structural equality check: ${Money.zero("usd") == Money.of(0.000, "USD")}") // true
}
```

## Lab 3: Reference Solution (Part 1 — Mapping Extensions)

// Assumes Money and OrderSnapshot from Lab 2 are in the same package/file

data class RawOrderPayload(
    val rawId: String?,
    val lineItems: List<String?>?,
    val rawAmount: Double?,
    val rawCurrency: String?
)

fun OrderSnapshot.toSummaryString(): String =
    "[ORDER #$orderId | STATUS: $status] Items (${items.size}): ${items.joinToString(", ")} | Total: $total"

---
```kotlin
fun RawOrderPayload?.toDomainOrder(): Result<OrderSnapshot> = runCatching {
    val payload = requireNotNull(this) { "Order payload cannot be null" }

    val cleanId = payload.rawId
        ?.trim()
        ?.takeIf { it.isNotBlank() }
        ?: throw IllegalArgumentException("Order ID is missing or blank")

    val cleanItems = payload.lineItems
        .orEmpty()
        .mapNotNull { item -> item?.trim()?.takeIf { it.isNotBlank() } }

    require(cleanItems.isNotEmpty()) {
        "Order [$cleanId] must contain at least one non-blank line item"
    }

    val validAmount = requireNotNull(payload.rawAmount) {
        "Order [$cleanId] is missing rawAmount"
    }

    val cleanCurrency = payload.rawCurrency
        ?.trim()
        ?.takeIf { it.isNotBlank() }
        ?: Money.DEFAULT_CURRENCY

    OrderSnapshot(
        orderId = cleanId,
        items = cleanItems,
        total = Money.of(amount = validAmount, currency = cleanCurrency)
    )
}
```

## Day 2 Recap & Key Takeaways

* **Push Nulls to the Boundaries:** Sanitize `T?` payloads at the controller/ingestion edge using `?.`, `?:`, and `mapNotNull` so core business services operate purely on non-null `T` types.
* **Ban Unjustified `!!`:** Replace `!!` with early-return Elvis guards or `requireNotNull(x) { "context" }`.
* **Value Semantics with `data class`:** Use `val`-only data classes and `.copy()` for thread-safe DTOs, events, and value objects—never for mutable Hibernate `@Entity` classes.
* **Extend, Don't Wrap:** Replace static `*Utils` and `*Converter` classes with focused extension functions and `companion object` factories.
