## Why Kotlin on the Backend?

* **Conciseness (~40% less code):** Readability and maintainability over ceremony.
* **Compile-Time Safety:** Nullability tracked in the type system (Topic 02 deep dive).
* **100% JVM & Java Interop:** Call existing Java libraries, Spring, Hibernate, and Jackson seamlessly.
* **First-Class Spring Boot Support:** Official support in Spring Framework 6+ and Spring Boot 3+.
* **Coroutines Ready:** High-throughput non-blocking I/O without complex reactive chains (Topic 05).

## Java vs. Kotlin: The Backend Reality

**Java (Verbose Ceremony — Pre-Record or Mutable DTOs)**
```java
public class PaymentRequest {

    private final BigDecimal amount;
    private final String currency;

    public BigDecimal getAmount() { return amount; }
```

```kotlin

    val accountId: String,
    val amount: BigDecimal,
    val currency: String = "EGP"
)
```

## How Kotlin Compiles to the JVM

```text
[ Source.kt ] + [ Legacy.java ]
       │               │
       ▼               ▼
  [ kotlinc (K2) ]  [ javac ]
       │               │
       ▼               ▼
     [ .class Bytecode ]
              │
              ▼
   [ JVM Runtime (JDK 17/21) ]
```

* `kotlinc` compiles `.kt` files into standard `.class` bytecode.
* To the JVM, Kotlin classes look just like compiled Java classes.
* Includes a tiny runtime (`kotlin-stdlib`) for core extensions and collection helpers.

# Module 3: Basic Syntax
### Variables, Type System, String Templates, and Functions

---

## Variables: `val` vs. `var`

* **`val` (Value — Read-Only Reference):**
  * Equivalent to `final` in Java. Cannot be reassigned.
  * **Backend Rule:** Always default to `val` for thread safety and predictability.
* **`var` (Variable — Mutable Reference):**
  * Can be reassigned to a new value of the same type.
* **`const val` (Compile-Time Constant):**
  * Top-level or inside `object`; primitives and `String` only.

```kotlin
const val DEFAULT_TIMEOUT_MS = 5000L

fun processOrder() {
    val orderId = "ORD-9921"       // Type inferred as String
    val maxRetries: Int = 3        // Explicit type annotation
    
    var currentAttempt = 0         // Mutable local counter
    currentAttempt += 1            // Valid
    // orderId = "ORD-9922"        // ❌ Compilation Error: Val cannot be reassigned
}
```

---

## Read-Only Reference $\neq$ Deep Immutability

A critical distinction for backend state management:

```kotlin
// 'val' locks the reference, NOT the internal contents of a mutable list
val activeConnections = mutableListOf("db-node-1", "db-node-2")
activeConnections.add("db-node-3") // ✅ Allowed! The reference didn't change.

// True read-only collection interface
val allowedRoles: List<String> = listOf("ADMIN", "AUDITOR")
// allowedRoles.add("GUEST")       // ❌ Unresolved reference: add
```

---

## Unified Type System (No Raw Primitives in Code)

In Java, you juggle `int` vs `Integer`, `long` vs `Long`, `double` vs `Double`.

In Kotlin, **everything is an object** at the source level, and the compiler optimizes to JVM primitives (`int`, `long`) automatically under the hood.

| Category | Kotlin Types | Notes |
| :--- | :--- | :--- |
| **Integers** | `Byte`, `Short`, `Int`, `Long` | Use `_` for readability: `1_000_000L` |
| **Floating Point** | `Float`, `Double` | For production money/currency, use `BigDecimal` (Topic 02 Lab)! |
| **Boolean & Char** | `Boolean`, `Char` | Strict booleans (`&&`, `\|\|`, `!`) |
| **Special Types** | `Any`, `Unit`, `Nothing` | `Any` = `Object`, `Unit` = `void`, `Nothing` = never returns |

---

## The Type Hierarchy: `Any`, `Unit`, and `Nothing`

Kotlin has a strictly defined, unified type hierarchy with clear top and bottom types:

* **`Any` (The Supertype of All Non-Null Types):** The root of the Kotlin class hierarchy (equivalent to `java.lang.Object`), declaring `equals()`, `hashCode()`, and `toString()`. `Any?` is the root of the entire nullable hierarchy.
* **`Unit` (The Void Replacement):** Corresponds to `void` in Java, but is a **real singleton object (`Unit`)**. Because it is a true object, functions returning `Unit` can implement generic interfaces (`() -> Unit`) without requiring a dummy `Void` class.
* **`Nothing` (The Bottom Type):** `Nothing` has **no instances**. It represents expressions that never complete successfully (e.g., functions that always throw an exception or enter an infinite loop):

```kotlin
// 1. throw evaluates to type Nothing, allowing direct Elvis short-circuiting:
fun extractBearerToken(authHeader: String?): String {
    return authHeader?.removePrefix("Bearer ")?.trim()
        ?: throw IllegalArgumentException("Missing or invalid Authorization header")
}

// 2. TODO() returns Nothing, satisfying any return type during prototyping:
fun calculateDynamicFee(orderId: String): Double {
    TODO("Pending partner interchange fee table implementation")
}
```

## Explicit Numeric Conversions

Kotlin **does not** implicitly widen numbers (prevents subtle precision/overflow bugs in financial/backend systems):

```kotlin
val retryCount: Int = 5
// val timeoutMs: Long = retryCount // ❌ Type mismatch: inferred type is Int but Long was expected

val timeoutMs: Long = retryCount.toLong() // ✅ Explicit conversion required
```

## Functions in Kotlin

* Declared with the `fun` keyword.
* Parameters are always `name: Type` (Pascal notation) and are **strictly read-only (`val`)**.

```kotlin
// 1. Standard Block-Body Function
fun calculateTax(amount: Double, taxRate: Double): Double {
    return amount * taxRate
}

// 2. Single-Expression Function (Return type inferred!)
fun calculateTaxShort(amount: Double, taxRate: Double) = amount * taxRate

// 3. Unit Return Type (Equivalent to Java 'void' - can be omitted)
fun auditLog(message: String) {
    println("[AUDIT] $message")
}
```

## Default Arguments & Named Parameters

Eliminates the "Telescoping Constructor / Method Overload" anti-pattern in Java backends:

```kotlin
fun createHttpClient(
    baseUrl: String,
    connectTimeoutMs: Long = 3_000L,
    readTimeoutMs: Long = 5_000L,
    enableRetry: Boolean = true,
    maxConnections: Int = 50
): String {
    return "Client[$baseUrl, conn=${connectTimeoutMs}ms, retry=$enableRetry, pool=$maxConnections]"
}

// Usage at Call-Site:
val defaultClient = createHttpClient("https://api.internal.io")

// Named arguments allow skipping middle defaults and self-documenting booleans:
val fastClient = createHttpClient(
    baseUrl = "https://auth.internal.io",
    enableRetry = false,
    maxConnections = 200
)
```

## Top-Level & Local Functions

* **Top-Level Functions:** Functions don't need to live inside a dummy `StringUtils` or `DateHelper` class. Put them directly in a `.kt` file!
* **Local Functions:** Functions inside functions to encapsulate helper validation logic without polluting class scope.

```kotlin
fun registerMerchant(name: String, taxId: String, iban: String) {
    // Local helper function - has access to outer parameters!
    fun validateField(value: String, fieldName: String) {
        if (value.isBlank()) {
            throw IllegalArgumentException("Merchant $fieldName cannot be blank")
        }
    }

    validateField(name, "Name")
    validateField(taxId, "Tax ID")
    validateField(iban, "IBAN")
    // Proceed with registration...
}
```

## Variable Arguments (`vararg`) & The Spread Operator (`*`)

Pass a variable number of parameters cleanly without creating arrays manually:

```kotlin
fun registerTenants(primaryTenant: String, vararg secondaryTenants: String) {
    println("Primary Tenant: $primaryTenant")
    for (tenant in secondaryTenants) {
        println("  Secondary Tenant: $tenant")
    }
}

// 1. Calling with comma-separated arguments:

// 2. Passing an existing array using the spread operator (*):
val partnerArray = arrayOf("Delta Co", "Epsilon Tech")
registerTenants("Acme Corp", *partnerArray) // Unpacks array into individual arguments
```

## Infix Functions (`infix fun`) for Expressive Domain Syntax

Define member or extension functions with a single parameter as `infix`, enabling clean, readable, natural-language DSLs and assertions without parentheses or dots:

```kotlin
data class Money(val amount: Long, val currency: String)

infix fun Long.of(currency: String): Money = Money(this, currency)

infix fun Money.transferTo(targetAccount: String) {
    println("Transferring $amount $currency to $targetAccount")
}

// Call site:
val fee = 500L of "EGP"
fee transferTo "ACC-9921"
```

## Idiomatic Preconditions: `require()`, `check()`, and Contracts

Instead of writing verbose `if (...) throw new ...` blocks, Kotlin's standard library provides built-in precondition functions backed by **Kotlin Compiler Contracts**:

| Function | Exception Thrown | When to Use |
| :--- | :--- | :--- |
| **`require(condition) { "msg" }`** | `IllegalArgumentException` | Validating **method/constructor arguments** passed by a caller |
| **`check(condition) { "msg" }`** | `IllegalStateException` | Validating the **internal state** of an object before an operation |
| **`requireNotNull(value) { "msg" }`** | `IllegalArgumentException` | Ensuring a critical parameter is non-null |

### How Compiler Contracts Enable Automatic Smart-Casting:
```kotlin
fun processTransfer(senderId: String?, balance: Double, isFrozen: Boolean) {
    // Contract: returns() implies (senderId != null)
    requireNotNull(senderId) { "senderId is required" }
    
    // senderId is automatically smart-cast from String? to non-null String!
    println("Processing transfer for sender: ${senderId.uppercase()}")

    require(balance > 0.0) { "Balance must be positive, got: $balance" }
    check(!isFrozen) { "Account is frozen; cannot initiate transfer" }
}
```

# Module 4: Control Flow & Loops
### Expressions Over Statements, Pattern Matching with `when`, and Ranges

---

## `if` is an Expression (Not Just a Statement)

In Kotlin, `if` returns a value. Therefore, **there is no ternary operator (`condition ? a : b`)** because `if-else` does it cleaner.

```kotlin
val currentLoad = 85

// Using 'if' as an expression assigned to a val
val routingStrategy = if (currentLoad > 80) {
    println("High load detected, throttling non-critical traffic")
    "THROTTLED_QUEUE" // Last expression in block is the return value
} else {
    "DIRECT_EXECUTION"
}
```

---

## `when` Expression: `switch` on Steroids

* Matches arbitrary expressions, multiple values, ranges (`in`), and types (`is`).
* No `break` needed (no accidental fall-through bugs).
* Compiler enforces **exhaustiveness** when used as an expression.

```kotlin
fun classifyHttpStatus(code: Int): String = when (code) {
    200, 201, 204 -> "SUCCESS"
    301, 302      -> "REDIRECT"
    in 400..499   -> "CLIENT_ERROR"
    in 500..599   -> "SERVER_ERROR"
    else          -> "UNKNOWN_STATUS ($code)"
}
```

---

## `when` Without an Argument & Smart-Cast Preview

Use `when` without `(subject)` to replace complex `if / else if` chains cleanly:

```kotlin
fun evaluateRiskLevel(amount: Double, isInternational: Boolean, accountAgeDays: Int): String = when {
    amount > 50_000.0 && isInternational -> "CRITICAL_MANUAL_REVIEW"
    amount > 10_000.0 || accountAgeDays < 7 -> "HIGH_RISK_2FA_REQUIRED"
    amount <= 0.0 -> throw IllegalArgumentException("Invalid transaction amount")
    else -> "LOW_RISK_AUTO_APPROVE"
}
```

---

## Ranges & Progressions

Kotlin represents intervals as first-class `ClosedRange` or `OpenEndRange` objects:

```kotlin
val inclusiveRange = 1..5           // 1, 2, 3, 4, 5
val halfOpenRange  = 0..<5          // 0, 1, 2, 3, 4 (Modern Kotlin 1.9+ syntax, replaces 'until')
val reverseRange   = 10 downTo 2    // 10, 9, 8 ... 2
val steppedRange   = 1..10 step 2   // 1, 3, 5, 7, 9

// Checking membership with 'in' / '!in'
val port = 8080
if (port in 1024..65535) {
    println("Valid unprivileged port")
}
```

---

## Loops: `for`, `while`, and Indexed Iteration

No C-style `for(int i=0; i<n; i++)`. Everything iterates over ranges or iterables:

```kotlin
val endpoints = listOf("/health", "/metrics", "/v1/orders")

// 1. Standard iteration
for (path in endpoints) {
    println("Registering route: $path")
}

// 2. Iteration with index destructuring
for ((index, path) in endpoints.withIndex()) {
    println("Route #$index -> $path")
}

// 3. Retry loop with range
for (attempt in 1..3) {
    println("Executing attempt $attempt")
}
```

## Lab 1: Backend Rate-Limiter & Fee Engine

**Scenario:** You are building a core pricing and rate-limiting utility for a FinTech API gateway *(Note: We use `Double` here for syntax simplicity; in Topic 02 we will build a strict `BigDecimal` `Money` class).*

**Tasks:**
1. Write a function `calculateTransactionFee` with parameters:
   * `amount: Double`
   * `tier: String = "STANDARD"`
   * `isCrossBorder: Boolean = false`
2. Use a `when` expression on `tier.uppercase()` to determine the base rate:
   * `"VIP"` $\rightarrow$ `0.0` (0%)
   * `"GOLD"` $\rightarrow$ `0.01` (1%)
   * `"STANDARD"` $\rightarrow$ `0.025` (2.5%)
   * Any other value $\rightarrow$ throw `IllegalArgumentException("Unsupported tier: $tier")`
3. If `isCrossBorder` is `true`, add a flat `15.0` fee (unless the tier is `"VIP"`, which pays `5.0`). Use an `if` expression!
4. Write a function `generateRetrySchedule(maxAttempts: Int = 4, baseDelayMs: Long = 100L): List<Long>` that uses a range loop (`0..<maxAttempts`) to calculate exponential backoff delays: $\text{baseDelayMs} \times 2^{\text{attempt}}$ (e.g., `100, 200, 400, 800`).

---

## Lab 1: Reference Solution (Part 1 — Fee Calculation)

```kotlin
fun calculateTransactionFee(
    amount: Double,
    tier: String = "STANDARD",
    isCrossBorder: Boolean = false
): Double {
    require(amount > 0) { "Amount must be positive, got $amount" }

    val normalizedTier = tier.uppercase()
    val percentageRate = when (normalizedTier) {
        "VIP" -> 0.0
        "GOLD" -> 0.01
        "STANDARD" -> 0.025
        else -> throw IllegalArgumentException("Unsupported tier: $tier")
    }

    val crossBorderSurcharge = if (!isCrossBorder) {
        0.0
    } else if (normalizedTier == "VIP") {
        5.0
    } else {
        15.0
    }

    return (amount * percentageRate) + crossBorderSurcharge
}
```

---

## Lab 1: Reference Solution (Part 2 — Backoff & Verification)

```kotlin
fun generateRetrySchedule(
    maxAttempts: Int = 4,
    baseDelayMs: Long = 100L
): List<Long> {
    val schedule = mutableListOf<Long>()
    for (attempt in 0..<maxAttempts) {
        val multiplier = 1L shl attempt // Bitwise shift: 2^attempt
        schedule.add(baseDelayMs * multiplier)
    }
    return schedule
}

fun main() {
    // Test with named & default arguments
    println("Standard Domestic: ${calculateTransactionFee(1000.0)}") // 25.0
    println("VIP Cross-Border: ${calculateTransactionFee(1000.0, tier = "vip", isCrossBorder = true)}") // 5.0
    println("Backoff Schedule: ${generateRetrySchedule(maxAttempts = 5)}") // [100, 200, 400, 800, 1600]
}
```

# Module 5: Classes, Properties & Constructors
### Object-Oriented Design Without the Ceremony

---

## Declaring Classes & Primary Constructors

* In Kotlin, classes are **`public` and `final` by default**.
* The **Primary Constructor** is part of the class header.
* Adding `val` or `var` to a constructor parameter both **declares a property** AND **initializes it**.

```kotlin
class ServiceEndpoint(
    val serviceName: String,          // Read-only property + getter
    val host: String,                 // Read-only property + getter
    var port: Int = 8080,             // Mutable property + getter & setter
    rawProtocol: String = "https"     // Plain constructor parameter (NOT a property! Used only during init)
) {
    val baseUrl: String = "${rawProtocol.lowercase()}://$host:$port"
}

// Instantiation (Notice: NO 'new' keyword in Kotlin!)
val endpoint = ServiceEndpoint("order-service", "10.0.1.15")
println(endpoint.baseUrl) // https://10.0.1.15:8080
```

---

## Initialization Order & `init` Blocks

Because the primary constructor cannot contain arbitrary statements, Kotlin provides **`init` blocks** that execute during instance creation in top-to-bottom order.

```kotlin
class BankAccount(
    val accountNumber: String,
    initialBalance: Double = 0.0
) {
    init {
        // Idiomatic precondition validation in Kotlin stdlib:
        require(accountNumber.isNotBlank()) { "Account number must not be blank" }
        require(initialBalance >= 0.0) { "Initial balance cannot be negative: $initialBalance" }
    }

    var balance: Double = initialBalance
        private set // External callers can read, only this class can modify!

    fun deposit(amount: Double) {
        require(amount > 0.0) { "Deposit must be positive" }
        balance += amount
    }
}
```

---

## Secondary Constructors

When a class needs multiple ways to be constructed that can't be covered by default parameters alone, use `constructor(...)` delegating via `: this(...)`:

```kotlin
import java.time.Instant

class AuditEvent(
    val eventType: String,
    val actorId: String,
    val timestampEpochMs: Long = Instant.now().toEpochMilli()
) {
    // Secondary constructor parsing a legacy delimited string "LOGIN:usr_123"
    constructor(rawLegacyPayload: String) : this(
        eventType = rawLegacyPayload.substringBefore(":"),
        actorId = rawLegacyPayload.substringAfter(":")
    ) {
        println("Constructed AuditEvent from legacy string format")
    }
}
```

---

## Properties vs. Fields (`field` Backing Identifier)

In Kotlin, you always access **properties**, never raw fields. Under the hood, Kotlin generates a private Java field and public getter/setter methods automatically.

```kotlin
class RateLimitConfig {
    // 1. Computed Property (No backing field stored in memory)
    val isProductionMode: Boolean
        get() = System.getenv("APP_ENV") == "PROD"

    // 2. Property with Custom Setter & 'field' keyword
    var requestsPerSecond: Int = 100
        set(value) {
            require(value in 1..10_000) { "RPS must be between 1 and 10,000" }
            field = value // 'field' refers to the hidden backing storage
        }
}
```

> **Trap to Avoid:** Writing `requestsPerSecond = value` inside `set(value)` causes an infinite recursion (`StackOverflowError`) because it calls the setter again! Always use `field = value`.

---

## Visibility Modifiers in Kotlin

Designed for modular architectures (Notice the replacement of Java's broken `package-private` with `internal`):

| Modifier | Class Member Meaning | Top-Level Declaration Meaning |
| :--- | :--- | :--- |
| **`public`** *(default)* | Visible everywhere | Visible everywhere |
| **`internal`** | Visible inside the **same Gradle/Maven module** | Visible inside the **same module** |
| **`protected`** | Visible in class and subclasses *(NOT same package!)* | *Not applicable at top-level* |
| **`private`** | Visible inside this class only | Visible inside **this `.kt` file only** |

---

## Inheritance & Interfaces (`open` vs `final`)

In *Effective Java*, Joshua Bloch advises: *"Design and document for inheritance or else prohibit it."* Kotlin enforces this by making classes and methods closed (`final`) by default.

```kotlin
interface NotificationSender {
    val channelName: String // Abstract property in interface!
    fun send(recipient: String, message: String): Boolean
    
    // Default interface implementation
    fun healthCheck(): String = "Channel [$channelName] is ONLINE"
}

open class BaseEmailSender(override val channelName: String = "SMTP") : NotificationSender {
    open fun formatBody(raw: String): String = raw.trim()

    override fun send(recipient: String, message: String): Boolean {
        val body = formatBody(message)
        println("Sending via $channelName to $recipient: $body")
        return true
    }
}
```

## Lab 2: Migrating a Legacy Java Domain Class

Refactor the following verbose 55-line Java class into idiomatic Kotlin in **under 35 lines**:

```java
// LegacySubscription.java
public class LegacySubscription {
    private final String id;
    private final String customerId;
    private String planCode;
    private int maxSeats;
    private boolean cancelled;

    public LegacySubscription(String id, String customerId) {

    }

    public LegacySubscription(String id, String customerId, String planCode, int maxSeats) {
        if (id == null || id.isBlank()) throw new IllegalArgumentException("id required");
        if (customerId == null || customerId.isBlank()) throw new IllegalArgumentException("customerId required");
        if (maxSeats < 1) throw new IllegalArgumentException("maxSeats must be >= 1");

        this.customerId = customerId;

        if (additionalSeats < 0) throw new IllegalArgumentException("Invalid seats");
        this.planCode = newPlan.toUpperCase();
        this.maxSeats += additionalSeats;
    }

    public void cancel() { this.cancelled = true; }
    public boolean isEnterprise() { return this.maxSeats >= 100 || "ENTERPRISE".equals(this.planCode); }
    // ... plus getters for all fields
}
```

## Lab 2: Reference Solution

```kotlin
class Subscription(
    val id: String,
    val customerId: String,
    planCode: String = "FREE",
    maxSeats: Int = 5
) {
    var planCode: String = planCode.uppercase()
        private set

    var maxSeats: Int = maxSeats
        private set

    var isCancelled: Boolean = false
        private set

    val isEnterprise: Boolean
        get() = maxSeats >= 100 || planCode == "ENTERPRISE"

    init {
        require(id.isNotBlank()) { "id required" }
        require(customerId.isNotBlank()) { "customerId required" }
        require(maxSeats >= 1) { "maxSeats must be >= 1" }
    }

    fun upgradePlan(newPlan: String, additionalSeats: Int = 0) {
        check(!isCancelled) { "Cannot upgrade cancelled subscription" }
        require(additionalSeats >= 0) { "Invalid seats" }
        planCode = newPlan.uppercase()
        maxSeats += additionalSeats
    }

    fun cancel() {
        isCancelled = true
    }
}
```

**Requirements:**

   * Maintain `var balance: Double = 0.0` with `private set`.
   * Implement `credit(amount: Double, note: String = "Deposit")` and `debit(amount: Double, note: String = "Withdrawal")` that validate amounts using `validate(amount)`, update `balance`, and append a formatted entry to `_history`.

## Lab 3: Reference Solution (Part 1 — `Wallet` Implementation)

```kotlin
interface TransactionValidator {
    fun validate(amount: Double): Boolean = amount > 0.0
}

class Wallet(
    val walletId: String,
    val ownerName: String,
    currency: String = "EGP"
) : TransactionValidator {
    val currency: String = currency.uppercase()

    var balance: Double = 0.0
        private set

    private val _history = mutableListOf<String>()
    val history: List<String>
        get() = _history.toList()

    init {
        require(walletId.isNotBlank()) { "Wallet ID cannot be blank" }
        require(ownerName.isNotBlank()) { "Owner name cannot be blank" }
        require(this.currency in setOf("EGP", "USD", "EUR")) {
            "Unsupported currency: ${this.currency}"
        }
    }

    fun credit(amount: Double, note: String = "Deposit") {
        require(validate(amount)) { "Credit amount must be positive" }
        balance += amount
        _history.add("[CREDIT] +$amount $currency ($note) | Bal: $balance")
    }

    fun debit(amount: Double, note: String = "Withdrawal") {
        require(validate(amount)) { "Debit amount must be positive" }
        check(balance >= amount) { "Insufficient funds: balance=$balance, requested=$amount" }
        balance -= amount
        _history.add("[DEBIT]  -$amount $currency ($note) | Bal: $balance")
    }
}
```

## Topic 01 Recap & Key Takeaways

* **Default to `val`:** Prefer read-only references and immutable collection interfaces (`List`, `Set`, `Map`).
* **The Unified Hierarchy:** Leverage `Any`, `Unit`, and `Nothing` for type-safe expression returns and Elvis short-circuits.
* **Eliminate Overloads:** Use default parameters, named arguments, and `vararg` instead of overloaded Java methods.
* **Expressions Over Statements:** Assign the result of `if` and `when` directly to `val`s or single-expression functions.
* **Encapsulate State:** Use primary constructors, `init` blocks with `require()`/`check()` contracts, and `private set` on mutable domain properties.
