## The Variance Problem: Why Java Wildcards Cause Pain

In Java, generic types are **invariant**. Even though `String` is a subtype of `Object`, `List<String>` is **not** a subtype of `List<Object>`. 

To allow flexibility, Java uses complex **use-site wildcards** (PECS: *Producer Extends, Consumer Super*):
```java
// Java: Must annotate every method parameter with wildcards!
void copyAccounts(List<? extends Account> source, List<? super Account> destination) { ... }
```

Kotlin simplifies this fundamentally with **Declaration-Site Variance**: you declare variance once on the class or interface definition itself!

---

## Covariance (`out T`): The Producer Rule

If a generic class only **produces / returns** `T` (read-only) and never consumes `T` as a parameter, annotate it with **`out`**:

* **Subtyping Guarantee:** If `Sub` extends `Super`, then `Producer<Sub>` is a subtype of `Producer<Super>`.
* **Standard Library Example:** `List<out E>` is covariant in Kotlin! `List<String>` can be passed directly to a function expecting `List<Any>`.

```kotlin
// Interface produces T (read-only output):
interface EventSource<out T> {
    fun nextEvent(): T
    fun getAllEvents(): List<T>
    // fun addEvent(event: T) // ❌ Compilation Error: Type parameter T is declared as 'out' but occurs in 'in' position
}

open class DomainEvent(val id: String)
class OrderCreatedEvent(id: String, val amount: Double) : DomainEvent(id)

fun processEvents(source: EventSource<DomainEvent>) {
    val event = source.nextEvent()
    println("Processed event: ${event.id}")
}

// Allowed because EventSource is covariant (out T):
val orderSource: EventSource<OrderCreatedEvent> = getOrderEventSource()
processEvents(orderSource) // ✅ Compiles cleanly without wildcard syntax!
```

## Contravariance (`in T`): The Consumer Rule

If a generic class only **consumes / accepts** `T` as a parameter and never produces `T`, annotate it with **`in`**:

* **Subtyping Guarantee:** If `Sub` extends `Super`, then `Consumer<Super>` is a subtype of `Consumer<Sub>` (the relationship is inverted!).
* **Standard Library Example:** `Comparable<in T>` is contravariant.

```kotlin
// Interface consumes T (write-only input):
interface EventHandler<in T> {
    fun handle(event: T)
}

// A handler that can process ANY generic DomainEvent:
val generalHandler: EventHandler<DomainEvent> = object : EventHandler<DomainEvent> {
    override fun handle(event: DomainEvent) {
        println("Logging event #${event.id} to audit log")
    }
}

// Can be safely assigned to a specific OrderCreatedEvent handler:
val orderHandler: EventHandler<OrderCreatedEvent> = generalHandler // ✅ Contravariant!
orderHandler.handle(OrderCreatedEvent("ORD-1", 250.0))
```

## Generic Constraints (`where` Clause)

Restricting type parameters to multiple bounds:

```kotlin
// Single upper bound:
fun <T : Number> calculateAverage(items: List<T>): Double {
    return items.map { it.toDouble() }.average()
}

// Multiple upper bounds using the 'where' clause:
fun <T> serializeAndIndex(item: T) where T : Serializable, T : Comparable<T> {
    println("Item has hashCode: ${item.hashCode()}")
}
```

## Overcoming JVM Type Erasure with `inline fun <reified T>`

On the JVM, generic type arguments are **erased** at runtime due to backward compatibility (`List<String>` becomes raw `List`). 

In Java and standard Kotlin functions, checking types or instantiating classes requires passing verbose `Class<T>` tokens:
```kotlin
// Without reified (clumsy Java style):
fun <T> parseJson(json: String, clazz: Class<T>): T { ... }
val user = parseJson(payload, UserDto::class.java)
```

By marking an `inline` function's type parameter as **`reified`**, the compiler inlines the actual type bytecodes directly at the call site, keeping the type information alive!

```kotlin
inline fun <reified T> parseJson(json: String): T {
    println("Inspecting runtime type: ${T::class.qualifiedName}")
    // You can use T::class, is T, as? T directly!
    return jacksonObjectMapper().readValue(json, T::class.java)
}

// Clean call-site without Class<T> parameter:
val user: UserDto = parseJson(userJson)
val isUser = payload is T // ✅ Allowed inside inline reified functions!
```

## Class Delegation (`by`): Zero-Boilerplate Decorator Pattern

In Java, decorating a repository (e.g. adding Redis caching or Micrometer metrics) requires writing a wrapper class that manually delegates dozens of boilerplate methods:
```java
// Java: 50+ lines of manual passthrough methods just to intercept one call!
public class CachedUserRepository implements UserRepository {
    private final UserRepository delegate;
    public User findById(String id) { /* caching logic */ }
    public void save(User u) { delegate.save(u); }
    public void delete(User u) { delegate.delete(u); }
    // ... repeat for every single interface method
}
```
---
In Kotlin, the **`by`** keyword delegates all interface methods to an underlying instance automatically, allowing you to override only the methods you want to customize:


```kotlin
interface PaymentRepository {
    fun save(paymentId: String, amount: Double)
    fun findById(paymentId: String): Double?
    fun delete(paymentId: String)
}

class MeteredPaymentRepository(
    private val inner: PaymentRepository
) : PaymentRepository by inner { // ✅ Automatically implements all methods!

    override fun save(paymentId: String, amount: Double) {
        val start = System.currentTimeMillis()
        inner.save(paymentId, amount) // Delegate to actual DB repository
        val elapsed = System.currentTimeMillis() - start
        println("[METRIC] PaymentRepository.save took ${elapsed}ms")
    }
    // findById and delete are transparently forwarded without any boilerplate!
}
```

## Thread-Safe Lazy Initialization: `by lazy`

Defer expensive object construction (database connection pools, cryptographic key loaders, WebClient instances) until first access:

```kotlin
class PaymentGatewayClient {
    // Computed exactly once on the first property read:
    val cryptoKey: ByteArray by lazy(LazyThreadSafetyMode.SYNCHRONIZED) {
        println("Loading 4096-bit RSA private key from Vault HSM...")
        // Costly I/O or crypto calculation
        ByteArray(512) { 0xFF.toByte() }
    }
}
```

### `LazyThreadSafetyMode` Options for Backend Engineers:
* **`SYNCHRONIZED` (Default):** Thread-safe. Uses an internal double-checked lock. Use for multi-threaded services.
* **`PUBLICATION`:** Multiple threads can compute the initializer concurrently, but only the first returned value is stored.
* **`NONE`:** No thread safety. Use only in single-threaded workers or CLI utilities for zero synchronization overhead.

## Auditing & Change Notification: `Delegates.observable`

Attach reactive callbacks to property mutations without writing custom setter boilerplate:

```kotlin
import kotlin.properties.Delegates

class MerchantSettings(val merchantId: String) {
    var feePercentage: Double by Delegates.observable(2.5) { property, oldValue, newValue ->
        println("[AUDIT] Merchant [$merchantId] ${property.name} changed from $oldValue% to $newValue%")
        // Emit audit event to Kafka or DB table
    }
}

val settings = MerchantSettings("MCH-44")
settings.feePercentage = 2.8 // Triggers audit callback immediately!
```

## Guarding Invariants: `Delegates.vetoable`

Validate business rules **before** mutating a property, vetoing illegal state transitions by returning `false`:

```kotlin
import kotlin.properties.Delegates

enum class AccountState { PENDING, ACTIVE, SUSPENDED, TERMINATED }

class BankAccount(val accountNumber: String) {
    var state: AccountState by Delegates.vetoable(AccountState.PENDING) { _, current, next ->
        val isLegalTransition = when (current) {
            AccountState.PENDING -> next == AccountState.ACTIVE || next == AccountState.TERMINATED
            AccountState.ACTIVE -> next == AccountState.SUSPENDED || next == AccountState.TERMINATED
            AccountState.SUSPENDED -> next == AccountState.ACTIVE || next == AccountState.TERMINATED
            AccountState.TERMINATED -> false // Terminal state: NEVER allows transition!
        }
        if (!isLegalTransition) {
            println("[VETO] Illegal transition attempted: $current -> $next")
        }
        isLegalTransition
    }
}

val account = BankAccount("ACC-901")
account.state = AccountState.ACTIVE     // Allowed! state is now ACTIVE
account.state = AccountState.TERMINATED // Allowed! state is now TERMINATED
account.state = AccountState.ACTIVE     // ❌ Vetoed! state remains TERMINATED
```

## Late Initialization: `Delegates.notNull()`

An alternative to `lateinit var` that works with **primitives** (`Int`, `Long`, `Double`) as well as objects:

```kotlin
class ServerConfiguration {
    // lateinit var port: Int // ❌ Compilation Error: lateinit not allowed on primitive types!
    var port: Int by Delegates.notNull()
}

val config = ServerConfiguration()
// println(config.port) // ❌ Throws IllegalStateException: Property port should be initialized before get.
config.port = 8080      // ✅ Initialized!
println(config.port)    // 8080
```

## Grouping and In-Memory Aggregations

Avoid expensive round-trips to SQL databases by performing complex aggregations cleanly in memory using `groupingBy`:

```kotlin
data class Transaction(val id: String, val merchant: String, val amount: Double, val currency: String)

val transactions = listOf(
    Transaction("T1", "Amazon", 450.0, "EGP"),
    Transaction("T2", "Noon", 120.0, "EGP"),
    Transaction("T3", "Amazon", 850.0, "EGP"),
    Transaction("T4", "Jumia", 300.0, "USD")
)

// 1. Counting occurrences per key:
val countByMerchant: Map<String, Int> = transactions
    .groupingBy { it.merchant }
    .eachCount()
// Result: {Amazon=2, Noon=1, Jumia=1}

// 2. Summing values per key using fold:
val volumeByMerchant: Map<String, Double> = transactions
    .groupingBy { it.merchant }
    .fold(0.0) { accumulator, tx -> accumulator + tx.amount }
// Result: {Amazon=1300.0, Noon=120.0, Jumia=300.0}
```

## Batching, Windowing & Partitioning

* **`chunked(size)`:** Splits a large list into fixed-size batches (e.g. batching 10,000 DB writes into chunks of 500).
* **`windowed(size, step)`:** Sliding windows for calculating moving averages or rate-limit anomaly detection.
* **`partition { predicate }`:** Splits a collection into two lists in a single pass (`Pair<Matching, NonMatching>`).

```kotlin
val orderIds = (1..10).map { "ORD-$it" }

// 1. Chunking into database batches of 3:
val batches: List<List<String>> = orderIds.chunked(3)
// [[ORD-1, ORD-2, ORD-3], [ORD-4, ORD-5, ORD-6], [ORD-7, ORD-8, ORD-9], [ORD-10]]

// 2. Partitioning valid vs invalid accounts in 1 pass:
val accounts = listOf("ACC-1", "INV-2", "ACC-3", "ERR-4")
val (valid, invalid) = accounts.partition { it.startsWith("ACC-") }
// valid = [ACC-1, ACC-3], invalid = [INV-2, ERR-4]
```

## Eager `Iterable` vs. Lazy `Sequence`

When processing collections with chaining operators (`filter`, `map`), standard Kotlin collections are **eager**: each step allocates an entirely new temporary list in memory!

```
[Eager Iterable]
Input (1,000,000 items) ---> filter() ---> Allocates List #1 (500,000 items)
                         ---> map()    ---> Allocates List #2 (500,000 items)
                         ---> first()  ---> Returns 1 item (Discards List #1 & #2 to GC!)

[Lazy Sequence]
Input (1,000,000 items) ---> filter -> map -> first() ---> Evaluates items ONE BY ONE!
                         (Stops immediately on the 1st match. Zero intermediate lists allocated!)
```

```kotlin
val firstSettledTx = largeTransactionDataset.asSequence()
    .filter { it.amount > 10_000.0 }
    .map { it.merchantId }
    .firstOrNull() // Short-circuits immediately!
```

## Lab 1: Type-Safe Event Bus with `reified` and Variance

**Scenario:** Build a decoupled in-memory domain event bus for a microservice order processing engine. Handlers must accept event types contravariantly (`in E : DomainEvent`), and the bus must allow type-safe registration using `reified`.

**Tasks:**
1. Define a base interface `DomainEvent(val eventId: String, val timestamp: Long)`.
2. Define two event types: `OrderCreatedEvent(eventId, timestamp, val orderId: String, val amount: Double)` and `FraudFlaggedEvent(eventId, timestamp, val accountId: String)`.
3. Create a contravariant event listener: `interface EventListener<in E : DomainEvent> { fun onEvent(event: E) }`.
4. Implement an `InMemoryEventBus` with:
   * `inline fun <reified E : DomainEvent> subscribe(listener: EventListener<E>)`
   * `inline fun <reified E : DomainEvent> publish(event: E)`

---

## Lab 1: Reference Solution

```kotlin
import kotlin.reflect.KClass

interface DomainEvent {
    val eventId: String
    val timestampMs: Long
}

data class OrderCreatedEvent(
    override val eventId: String,
    override val timestampMs: Long,
    val orderId: String,
    val amount: Double
) : DomainEvent

data class FraudFlaggedEvent(
    override val eventId: String,
    override val timestampMs: Long,
    val accountId: String,
    val reason: String
) : DomainEvent

interface EventListener<in E : DomainEvent> {
    fun onEvent(event: E)
}
```
---
```kotlin

class InMemoryEventBus {
    val registry = mutableMapOf<KClass<*>, MutableList<EventListener<*>>>()

    inline fun <reified E : DomainEvent> subscribe(listener: EventListener<E>) {
        val listeners = registry.getOrPut(E::class) { mutableListOf() }
        listeners.add(listener)
    }

    @Suppress("UNCHECKED_CAST")
    inline fun <reified E : DomainEvent> publish(event: E) {
        val listeners = registry[E::class] as? List<EventListener<E>> ?: emptyList()
        for (listener in listeners) {
            listener.onEvent(event)
        }
    }
}
```
---
```kotlin
fun main() {
    val bus = InMemoryEventBus()

    bus.subscribe<OrderCreatedEvent>(object : EventListener<OrderCreatedEvent> {
        override fun onEvent(event: OrderCreatedEvent) {
            println("[ORDER SERVICE] Created Order #${event.orderId} for $${event.amount}")
        }
    })

    bus.subscribe<FraudFlaggedEvent>(object : EventListener<FraudFlaggedEvent> {
        override fun onEvent(event: FraudFlaggedEvent) {
            println("[FRAUD ALERT] Account ${event.accountId} flagged: ${event.reason}")
        }
    })

    bus.publish(OrderCreatedEvent("EVT-1", System.currentTimeMillis(), "ORD-99", 420.50))
    bus.publish(FraudFlaggedEvent("EVT-2", System.currentTimeMillis(), "ACC-501", "Rapid high-value transfers"))
}
```

```kotlin
// 2. Standard library property delegates
class MerchantFeePolicy(val merchantId: String) {
    // Lazy expensive initialization
    val auditClient: String by lazy(LazyThreadSafetyMode.SYNCHRONIZED) {
        println("Connecting to secure Audit Vault HSM...")
        "VAULT-CLIENT-SECURE"
    }

    // Observable change auditing
    var tier: String by Delegates.observable("STANDARD") { prop, old, new ->
        println("[AUDIT via $auditClient] Merchant [$merchantId] ${prop.name} upgraded: $old -> $new")
    }

    // Vetoable business invariant check

            println("[VETO] Rejected fee update to $candidate%. Must be between 0.1% and 15.0%")
        }
        isValid
    }
}
```

## Lab 3: Big Data Settlement Pipeline with `Sequence` and `groupingBy`

**Scenario:** Ingest a batch of 100,000 settlement records. Group them by currency to compute the total settlement amount and fee revenue without creating millions of intermediate heap objects.

---

## Lab 3: Reference Solution

```kotlin
data class SettlementRecord(
    val id: String,
    val currency: String,
    val grossAmountPiasters: Long,
    val feePiasters: Long
)

fun generateSettlementRecords(count: Int): Sequence<SettlementRecord> = sequence {
    val currencies = listOf("EGP", "USD", "EUR", "AED")
    for (i in 1..count) {
        yield(
            SettlementRecord(
                id = "SETTLE-$i",
                currency = currencies[i % currencies.size],
                grossAmountPiasters = 100_000L + (i * 10L),
                feePiasters = 2500L
            )
        )
    }
}

```
---
```kotlin

fun main() {
    val stream = generateSettlementRecords(100_000)

    // Lazy sequence processing: 0 intermediate list allocations!
    val volumeByCurrency: Map<String, Long> = stream
        .filter { it.grossAmountPiasters > 100_500L }
        .groupingBy { it.currency }
        .fold(0L) { acc, record -> acc + record.grossAmountPiasters }

    println("Settlement Totals by Currency:")
    volumeByCurrency.forEach { (curr, total) ->
        val egpEquivalent = total / 100.0
        println("  $curr: $egpEquivalent units")
    }
}
```

## Topic 03 Recap & Key Takeaways

* **Declaration-Site Variance:** Use `out T` for producer interfaces and `in T` for consumer/handler interfaces to prevent PECS boilerplate.
* **Inline Reified Types:** Use `inline fun <reified T>` to retain generic types at runtime, eliminating `Class<T>` tokens in JSON parsing and event dispatching.
* **Class Delegation (`by`):** Decorate interfaces in 1 line of code, overriding only targeted methods while forwarding the rest cleanly.
* **Property Delegation Toolkit:**
  * `by lazy`: Thread-safe deferred initialization (`SYNCHRONIZED`).
  * `Delegates.observable`: Real-time audit logging on assignment.
  * `Delegates.vetoable`: Business invariant validation before mutating state.
* **Stream Performance with `Sequence`:** Use `asSequence()` for multi-step pipelines on large collections to avoid intermediate list heap allocations.
